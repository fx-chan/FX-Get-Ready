> Підготовка до проміжного тесту в CPUSim: за 100 хвилин написати на асемблері симуляцію простої гри (Sokoban, Tetris, Змійка …). Урок розглядає інструкції й адресацію, типові конструкції та каркас розв'язання; завдання йдуть від коротких циклів до цілих ігор з минулих тестів.

## Який вигляд має тест

- Ви розв'язуєте в **базовому симуляторі** CPUSim (von Neumann, 2048 слів по 32 біти). Програма належить до комірок **0 – 1023**, дані починаються від **1024**.
- Вхідні дані (розміри, матриці, послідовність команд) уже лежать у пам'яті тесту, область програми порожня. Завдання точно визначає, за якими адресами записати результати та які комірки вільні для ваших змінних.
- Програма має працювати для **всіх допустимих вхідних даних** — екзаменатор запустить її й на інших даних, ніж у прикладі. Жорстко задані розміри в програмі — певна втрата балів.
- Наприкінці відкриваєте `Riešenie na odovzdanie` → `Kopírovať` і весь текст (заголовок, PROGRAM, DATA, END) вставляєте у відповідь в UIS без змін.

### Робота в симуляторі

- **Ctrl+E** відкриває текстовий редактор: ліворуч пам'ять інструкцій (від 0), праворуч пам'ять даних (від 1024). Кожен рядок — одна комірка, порожній рядок — порожня комірка, рядок лише з коментарем комірку не займає.
- Під час тесту записуйте лише `Zapísať do pamäte inštrukcií` — `Zapísať všetko` перезаписало б підготовлені дані.
- **F8** (швидка симуляція) виконує за раз задану кількість мікроінструкцій (за замовчуванням 2000). Довшу програму треба запускати кілька разів або збільшити кількість у налаштуваннях інтервалів. **F7** виконує одну інструкцію, **Ctrl+B** ставить точку зупинки.
- Симуляція змінює пам'ять. Перед наступним запуском поверніть пам'ять до стану перед симуляцією (кнопка зі стрілкою назад), інакше програма працюватиме на вже змінених даних.

## Процесор та інструкції

Процесор має акумулятор **ACC**, лічильник інструкцій **PC**, регістр інструкції **IR**, адресний регістр **MAR**, регістр даних **MBR** і регістр стану **SR** з прапорцями C, V, N, Z. Майже все йде через ACC: завантаж, обчисли, збережи.

Інструкція має 32 біти: операнд (24 біти), спосіб адресації (2 біти) і код операції (6 біт).

| група | інструкції | що роблять |
|---|---|---|
| пересилання | `LOAD x`, `STORE x` | ACC ← операнд, пам'ять ← ACC |
| арифметика | `ADD`, `SUB`, `MUL`, `DIV` | ACC ← ACC op операнд (DIV цілочисельно) |
| на одиницю | `INC`, `DEC` | ACC ± 1, без операнда |
| порозрядні | `AND`, `OR`, `XOR`, `NOT` | порозрядно |
| зсуви | `ROL`, `ROR`, `RLV`, `RRV` | зсув ACC на біт (ROL = множення на два) |
| порівняння | `CMP x` | C ← 1, якщо ACC = операнд, інакше 0; ACC не змінюється |
| переходи | `JMP`, `JZ`, `JNZ`, `JC`, `JNC` | завжди / якщо ACC = 0 / якщо ACC ≠ 0 / якщо C = 1 / якщо C = 0 |
| інші | `HALT`, `NOP`, `CLSR` | кінець, нічого, обнулення SR |

У код можна писати **мітки** (`slucka:` перед інструкцією) і **коментарі** після крапки з комою. Числа також як `0x1F` чи `0b101`.

::: quiz
Що зробить `CMP 1026`, якщо в ACC значення 5 і в комірці 1026 теж 5?
- [ ] обнулить ACC
- [x] встановить прапорець C у 1 і залишить ACC без змін
- [ ] перейде на адресу 1026
> CMP лише порівнює на рівність і зберігає результат у C; для рішення потрібен ще JC або JNC.
:::

## Три способи адресації

| запис | назва | операнд — це |
|---|---|---|
| `LOAD #5` | безпосередня | саме число 5 |
| `LOAD 1025` | пряма | вміст комірки 1025 |
| `LOAD [1050]` або `LOAD @1050` | непряма | вміст комірки, адреса якої лежить у комірці 1050 |

Непряма адресація — ключ до масивів і матриць: у робочій комірці тримаємо **вказівник** (адресу елемента), а через `[ ]` читаємо або записуємо елемент, на який він вказує. Перехід до наступного елемента = збільшити вказівник.

`STORE` не має безпосередньої форми (у число записувати не можна); `STORE [p]` записує ACC за адресою, що лежить у `p`.

::: drill d10-adresovanie

::: quiz
У комірці 1050 лежить 1203, а в комірці 1203 — 4. Що буде в ACC після `LOAD [1050]`?
- [ ] 1050
- [ ] 1203
- [x] 4
> Непряма: спочатку з комірки 1050 читається адреса 1203, потім значення з комірки 1203.
:::

## Найчастіша помилка: переходи без #

Переходи беруть ціль як операнд так само, як LOAD. Тому:

- `JMP #slucka` переходить на мітку `slucka` — **це потрібно майже завжди**;
- `JMP slucka` переходить на адресу, що **лежить у комірці** `slucka` (але там закодована інструкція, тож процесор відскочить кудись у невідоме).

Те саме стосується `JZ`, `JNZ`, `JC`, `JNC`. Коли програма «робить дурниці» відразу після першого переходу, перевірте, чи не пропущено #.

::: quiz
Програма містить `JNZ slucka`. Куди перейде, якщо ACC ≠ 0?
- [ ] на інструкцію з міткою `slucka`
- [x] на адресу, що лежить у комірці `slucka`
- [ ] нікуди, це синтаксична помилка
> Без # це пряма адресація: ціль читається з пам'яті. Правильно `JNZ #slucka`.
:::

## Умови

У CPUSim немає переходу „якщо менше“. Умови складаються з того, що є:

| умова | код |
|---|---|
| x = 0 | `LOAD x`, `JZ #ano` |
| x = k (константа) | `LOAD x`, `CMP #k`, `JC #ano` |
| x = y | `LOAD x`, `CMP y`, `JC #ano` |
| x = R + 1 | `LOAD x`, `SUB R`, `DEC`, `JZ #ano` |
| x < y (малі числа) | `LOAD x`, `SUB y`, `AND #-8388608`, `JNZ #ano` |

Останній рядок: різниця від'ємна саме тоді, коли має встановлений старший біт; `#-8388608` має одиниці у верхніх дев'яти бітах, тож AND ненульовий лише для від'ємних чисел (для різниць менших за $2^{23}$).

У симуляціях ігор здебільшого досить рівності: координата поза картою, коли вона **0** або **R + 1** (відповідно C + 1), бо змінюється завжди лише на 1.

Увага, `STORE` не змінює значення в ACC, але `CMP` змінює прапорець C. Тому після `CMP` переходьте одразу.

::: drill d10-porovnanie

::: quiz
Робот у рядку 1 і отримує команду „вгору“. Новий рядок — 0. Як це найпростіше виявити?
- [ ] `CMP #-1` і `JC`
- [x] `LOAD nove_r` і `JZ #mimo`
- [ ] `AND #1` і `JNZ`
> Рядки нумеруються з 1, тож 0 означає поза картою, а JZ перевіряє це без порівняння.
:::

## Цикл по послідовності з маркером −1

Команди гри лежать підряд від якоїсь адреси й закінчуються значенням −1. Каркас:

```
        LOAD #1200
        STORE 1950      ; ukazovatel na aktualny prikaz
cyklus: LOAD [1950]
        CMP #-1
        JC #koniec      ; znacka - koniec simulacie
        ...             ; spracovanie prikazu (je v ACC)
        LOAD 1950
        INC
        STORE 1950
        JMP #cyklus
koniec: ...             ; zapis vystupov
        HALT
```

Розгалуження за кодом команди: `CMP #1`, `JC #hore`, `CMP #2`, `JC #dole` … — ACC при CMP не змінюється, тож порівнювати можна кілька разів поспіль. Якщо код можна використати як зсув адреси (лічильник команди $k$ на $1040 + k$), розгалуження не потрібне взагалі.

::: drill d10-sucet

## Матриці в пам'яті

Матриця $R \times C$, збережена по рядках від адреси $Z$: клітинка $(r, c)$ (нумерація з 1) лежить на $$Z + (r-1) \cdot C + (c-1)$$

```
        LOAD r
        DEC
        MUL 1026        ; (r-1)*C
        ADD c
        ADD #1099       ; + (c-1) + 1100
        STORE 1960      ; adresa policka
        LOAD [1960]     ; hodnota policka
```

Сусіди клітинки з адресою $A$: ліворуч $A - 1$, праворуч $A + 1$, вгорі $A - C$, внизу $A + C$. Якщо в пам'яті є дві матриці однакової форми (місцевість від 1100, ящики від 1800), та сама клітинка в другій лежить далі на **різницю початків** (тут +700).

У тесті завжди читайте точну формулу — в Tetris було $1100 + (r-1) \cdot C + c$, тобто матриця починалася на 1101.

::: quiz
Матриця має $C = 6$ стовпців. Клітинка має адресу 1123. Яка адреса клітинки прямо під нею?
- [ ] 1124
- [x] 1129
- [ ] 1117
> На рядок нижче = на C комірок далі: 1123 + 6.
:::

## Каркас симуляції гри

Усі тести мають однакову будову, змінюється лише те, що відбувається під час однієї команди:

1. **Ініціалізація.** Скопіюйте початкову позицію в робочі комірки, лічильники обнуліть, вказівник встановіть на першу команду. За потреби пройдіть по матриці й визначте суми (кількість ящиків, яблук, ящиків на цілі).
2. **Перевірка перед першою командою** (напр. перемога вже на початку).
3. **Головний цикл:** прочитай команду, якщо −1 → кінець; збільш час; обчисли нову позицію; перевір краї та вміст матриць; якщо можна, перемісти й онови лічильники; перевір кінець гри; посунь вказівник.
4. **Виходи:** перепишіть лічильники й позицію за адресами із завдання та `HALT`.

Корисні прийоми:

- **Напрям як пара** $(dr, dc)$ і зсув адреси $d = dr \cdot C + dc$ — клітинка перед гравцем це $P + d$, за ящиком $P + 2d$. MUL і ADD працюють з від'ємними числами.
- **Нову позицію обчислюйте окремо** і в справжню записуйте лише після всіх перевірок — заблокований рух тоді нічого не зіпсує.
- **Список (тіло змійки)** як пари від 1800: сегмент $i$ на $1800 + 2i$. Зсув тіла йде від хвоста: сегмент $i$ отримує значення сегмента $i - 1$.
- Виходи записуйте лише наприкінці одним блоком — кожна гілка завершення гри переходить на ту саму мітку.

::: quiz
Команду не можна виконати, бо гравець зайшов би в стіну. Що збільшується згідно з типовим завданням?
- [x] лише час симуляції
- [ ] і час, і кількість кроків
- [ ] нічого
> Час враховує оброблені команди (також заблоковані), кроки — лише справжні переміщення.
:::

## Налагодження та перевірка перед здачею

- Програма, що доходить до порожньої комірки, завершується помилкою — бракує `HALT` або переходу назад у цикл.
- Повідомлення `Čítanie z prázdnej bunky` означає, що програма читає змінну, в яку ще нічого не записано (або неправильну адресу).
- Повідомлення `Zápis do pamäte inštrukcií` означає запис за адресою нижче 1024 — майже завжди помилка в адресі.
- Спробуйте крайові випадки: порожню послідовність (−1 одразу на початку), рух до краю карти, кінець гри перед маркером, мінімальні й максимальні розміри.
- Точка зупинки на початку головного циклу та F8 покажуть стан після кожної команди.

::: quiz
Програма має обчислити результат для карти довільного розміру. Звідки брати кількість стовпців?
- [ ] з константи `#7`, якщо в прикладі C = 7
- [x] з комірки із вхідним параметром (напр. `MUL 1026`)
- [ ] з кількості рядків програми
> Екзаменатор запускає програму й на інших картах; розміри завжди читаються з пам'яті.
:::
