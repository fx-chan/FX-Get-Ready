## Багатовимірні масиви

```c
#define N 20
int m[N][N];                 // статичний 2D-масив: N рядків по N елементів, у пам'яті поспіль
m[i][j] = 5;                 // рядок i, стовпець j

void vypis(int m[][N], int n);   // під час передавання у функцію має бути відома кількість стовпців
```

Чотири способи створити 2D-масив (лекція P6):

| запис | рядки | стовпці | пам'ять |
|---|---|---|---|
| `int m[3][4];` | статичні | статичні | один суцільний блок, рядок за рядком |
| `int *p[3];` — **масив вказівників** | статичні (3) | динамічні, кожен рядок інший | `p[i] = malloc(...)` |
| `int (*p)[4];` — **вказівник на масив** | динамічні | статичні (4) | `p = malloc(n * sizeof *p);` один блок |
| `int **p;` — **вказівник на вказівник** | динамічні | динамічні | масив вказівників + блок для кожного рядка |

У всіх випадках до елемента звертаємось однаково: `p[i][j]`.

```c
int n = 3, k = 4;
int **p = malloc(n * sizeof(int *));      // 1. масив вказівників на рядки
for (int i = 0; i < n; i++)
    p[i] = malloc(k * sizeof(int));       // 2. кожен рядок окремо

for (int i = 0; i < n; i++)               // звільнення у ЗВОРОТНОМУ порядку:
    free(p[i]);                           //    спочатку рядки,
free(p);                                  //    потім масив вказівників
```

- **прямокутний масив** — усі рядки однакової довжини,
- **зубчастий масив** (jagged) — рядки різної довжини (напр. трикутник, масив рядків різної довжини); можливий лише через масив вказівників або `int **`,
- під час передавання у функцію: статичний `int m[][N]` (стовпці мають бути відомі), динамічний `int **p`,
- ініціалізація: `int m[2][3] = {{1, 2, 3}, {4, 5, 6}};` або `int m[][3] = {1, 2, 3, 4, 5, 6};`.

::: quiz
Чому для `int **p` спочатку треба звільнити `p[i]` і лише потім `p`?
- [ ] порядок не важливий
- [x] після `free(p)` ми втратили б адреси рядків — лишився б витік пам'яті (а читання `p[i]` після free — помилка)
- [ ] `free(p)` автоматично звільняє й рядки
> `free` звільняє лише один блок. Рядки — це окремі блоки, а їхні адреси зберігаються саме в `p`.
:::

## Рекурсія

Рекурсивна функція викликає сама себе. Їй потрібна **умова завершення** — інакше стек переповниться.

```c
long faktorial(int n) {
    if (n <= 1)                      // умова завершення
        return 1;
    return n * faktorial(n - 1);     // рекурсивний виклик із меншою задачею
}
```

::: quiz
Що поверне `f(4)`, якщо `int f(int n) { return n == 0 ? 0 : n + f(n - 1); }`?
- [ ] 4
- [x] 10
- [ ] 24
- [ ] нескінченна рекурсія
> 4 + 3 + 2 + 1 + 0 = 10.
:::

**Числа Фібоначчі** — рекурсія й ітерація:

```c
long fib_r(int n) {                    // коротко, але експоненційно повільно:
    if (n < 2) return n;               // fib_r(40) викликає сама себе сотні мільйонів разів
    return fib_r(n - 1) + fib_r(n - 2);
}

long fib_i(int n) {                    // цикл: n кроків, жодного стека
    long a = 0, b = 1;
    for (int i = 0; i < n; i++) { long t = a + b; a = b; b = t; }
    return a;
}
```

- кожен виклик виділяє на **стеку** місце для параметрів і локальних змінних — надто глибока рекурсія закінчується переповненням стека (segfault),
- рекурсія природна для дерев, поділу задачі навпіл (двійковий пошук), перестановок; просте повторення краще робити циклом,
- **налагодження**: виводьте параметр і глибину на вході й виході — `printf("%*sfib(%d)\n", hlbka * 2, "", n);` покаже дерево викликів із відступами за глибиною.

::: quiz
Скільки разів викликається `fib_r` під час обчислення `fib_r(4)` (разом із першим викликом)?
- [ ] 4
- [ ] 5
- [x] 9
- [ ] 16
> fib(4) → fib(3) + fib(2); fib(3) → fib(2) + fib(1); кожне fib(2) → fib(1) + fib(0). Разом 1 + 2 + 4 + 2 = 9 викликів.
:::

## Сталі змінні

```c
const double PI = 3.14159;      // значення змінювати не можна
void vypis(const char *s);      // функція обіцяє, що рядок не змінить
```

Для вказівників важливо, **де** стоїть `const`:

| запис | змінювати `*p` (дані) | змінювати `p` (адресу) |
|---|---|---|
| `const int *p` (= `int const *p`) — вказівник на сталу | ні | так |
| `int *const p = &x;` — сталий вказівник | так | ні |
| `const int *const p = &x;` | ні | ні |

Читайте справа наліво: `int *const p` = «p — сталий вказівник на int». Рядкову сталу `"ahoj"` змінювати не можна — тому `const char *s = "ahoj";`. На відміну від `#define`, змінна `const` має тип, і компілятор її перевіряє.

::: quiz
`int x = 1, y = 2; int *const p = &x;` Яка команда **помилкова**?
- [ ] `*p = 5;`
- [x] `p = &y;`
- [ ] `x = *p + 1;`
> `p` — сталий вказівник: адресу змінити не можна, а дані, на які він вказує, можна.
:::

## Власні типи даних: struct, typedef, enum, union

```c
typedef struct {
    char meno[101];
    int vek;
    double plat;
} OSOBA;

OSOBA o = {"Jan Novak", 30, 1500.0};
OSOBA *p = &o;
printf("%s %d\n", o.meno, o.vek);    // доступ через змінну: крапка
p->vek++;                            // доступ через вказівник: стрілка, те саме, що (*p).vek++

typedef enum { PONDELOK, UTOROK, STREDA } DEN;   // іменовані цілі числа 0, 1, 2
union cislo { int i; double d; };   // усі поля спільно використовують ту саму пам'ять
```

::: quiz
`OSOBA *p = &o;` Як змінити вік особи через `p`?
- [ ] `p.vek = 31;`
- [x] `p->vek = 31;`
- [ ] `*p.vek = 31;`
> `*p.vek` обчислюється як `*(p.vek)` — помилка. Правильно `p->vek` або `(*p).vek`.
:::

### Структури у функціях і динамічне виділення

```c
void vypis(OSOBA o);          // отримує КОПІЮ всієї структури (повільно для великих структур)
void zvys(OSOBA *o);          // отримує адресу — може змінювати оригінал, копіюється лише адреса
void tlac(const OSOBA *o);    // адреса, але без можливості зміни

OSOBA *d = malloc(sizeof(OSOBA));    // динамічна структура
d->vek = 20;                         // через вказівник завжди ->
free(d);

OSOBA tim[10];                       // масив структур
tim[0].vek = 25;                     // елемент масиву — структура → крапка
OSOBA *dt = malloc(n * sizeof(OSOBA));   // динамічний масив структур
dt[i].vek = 30;                      // dt[i] — структура → крапка; (dt + i)->vek те саме
```

### Копіювання: поверхнева і глибока копія

Структури **можна** копіювати присвоєнням `b = a;` (на відміну від масивів) — копіюється кожен байт, зокрема й масив усередині структури. Але якщо структура містить **вказівник**, копіюється лише адреса:

```c
typedef struct { char *meno; int vek; } OSOBA;

OSOBA b = a;                                // поверхнева копія: b.meno == a.meno (той самий блок!)
b.meno = malloc(strlen(a.meno) + 1);        // глибока копія: власна пам'ять
strcpy(b.meno, a.meno);                     // ... і скопійований вміст
```

У поверхневій копії зміна `a.meno[0]` змінює і `b.meno`, а подвійний `free` того самого блоку — помилка. Структури не можна порівнювати через `==` — порівнюйте поле за полем.

::: quiz
`typedef struct { char meno[20]; } A;` `A x = {"Eva"}, y = x; y.meno[0] = 'A';` Що в `x.meno`?
- [x] `Eva`
- [ ] `Ava`
- [ ] помилка компіляції
> Масив **усередині** структури під час присвоєння копіюється повністю — `y` має власну копію. Проблема виникає лише з вказівником `char *meno`.
:::

### enum і union докладніше

```c
typedef enum { NEPRAVDA, PRAVDA } LOGICKA;           // 0, 1
enum farba { CERVENA = 1, ZELENA, MODRA = 10, BIELA }; // 1, 2, 10, 11 — продовжує від останньої

const char *nazvy[] = {"PONDELOK", "UTOROK", "STREDA"};
DEN d = UTOROK;
printf("%d %s\n", d, nazvy[d]);     // 1 UTOROK — ім'я елемента можна вивести лише через масив рядків
```

`union` має розмір **найбільшого** поля; у кожен момент чинне лише одне з них. Часто вкладається у структуру разом із полем, яке каже, що зараз збережено:

```c
typedef struct {
    enum { CELE, REALNE } typ;
    union { int i; double d; } hodnota;
} CISLO;

CISLO c = { .typ = REALNE, .hodnota.d = 2.5 };
if (c.typ == REALNE) printf("%g\n", c.hodnota.d);
```

::: quiz
`enum { A, B = 5, C };` Яке значення має `C`?
- [ ] 2
- [x] 6
- [ ] 0
> Без явного значення елемент продовжує на 1 від попереднього: B = 5, C = 6.
:::

::: quiz
`union U { char c; int i; double d; };` Яке типове значення `sizeof(union U)`?
- [ ] 13
- [x] 8
- [ ] 1
> Поля спільно використовують пам'ять, union завбільшки з найбільше поле (`double` = 8 B).
:::
